# Lzhecord 0.8.0 — GPU/NVIDIA для проверки с друзьями

Новый **тестовый способ передачи монитора**: захват в D3D11-текстуры → аппаратное кодирование H.264 NVENC → готовый поток через WebRTC зрителям. Сырые видеокадры не проходят через Node/HTTP-мост. Один сеанс кодирования обслуживает всех зрителей; исходящий трафик по-прежнему расходуется отдельно на каждого.

## Что изменилось

- В выборе источника виден переключатель способов: обычный, **GPU/NVIDIA (beta)** и резервный. GPU пока поддерживает монитор и до 60 FPS; окна работают обычным способом.
- Исходный размер захватывается через DXGI, уменьшенный — через Windows Graphics Capture с масштабированием на GPU. Это обходит обнаруженную несовместимость отдельного D3D11-масштабировщика FFmpeg с драйвером NVENC.
- Системный звук передаётся Opus. Переключатель исключения звука Lzhecord сохраняет разговор и не возвращает голоса друзей в трансляцию.
- Микрофоны, личная громкость, подключение зрителя к уже идущему показу и смена показывающего экран работают с новым потоком.
- Смена разрешения/FPS/битрейта перезапускает только видео и переподключает зрителей, сохраняя голосовую комнату.
- Компоненты FFmpeg LGPL shared и MediaMTX загружаются один раз у ведущего с проверкой закреплённых SHA-256. Зрителям загрузка не нужна.
- Видеосигналы идут через текущую комнату с проверкой участника и владельца трансляции. Сетевые адреса GPU-видео ограничены Radmin; служебные HTTP/RTSP доступны только локально.
- Обычный и резервный захваты сохранены. Старая сборка 0.7.0 остаётся отдельным архивом.

## Как проверить

1. **Обновитесь до 0.8.0 всей компанией.** Протокол комнат изменён: версии 0.7.0 и 0.6.3 к новым комнатам не подключаются.
2. Скачайте `Lzhecord-Desktop-0.8.0-win-x64.zip`, распакуйте целиком в новую папку. Закройте старую версию и запустите `Lzhecord.exe`.
3. Подключитесь к одной сети Radmin, создайте комнату и пригласите друзей.
4. На ПК с NVIDIA/NVENC нажмите «Показать экран» → **GPU/NVIDIA** → монитор. Включите системный звук и исключение звука комнаты. При первом запуске дождитесь загрузки около 110 МБ с GitHub.
5. Разрешите **MediaMTX** связь через Radmin в брандмауэре на ПК показывающего экран: используется **UDP 8790**. Попробуйте исходное разрешение / 60 FPS / 20 Мбит/с, затем уменьшите настройки при задержках.

## Проверка и ограничения

На машине разработки проверен собранный Windows EXE: реальное GPU-кодирование монитора, несколько локальных зрителей, H.264/Opus, исключение контрольного звука Lzhecord при сохранении звука внешнего процесса, личная громкость, микрофон, позднее подключение, изменение разрешения, передача показа гостю и остановка дочерних процессов. Также выполнены автоматические проверки сетевой изоляции, владения захватом и существующего поведения приложения.

Предварительное сравнение прототипа на RTX 2060 SUPER / 3440×1440 с тремя локальными зрителями показало около **36 → 57 наблюдаемых кадров/с**, **184–202 → около 75 мс** задержки и **56% → около 12%** суммарной загрузки CPU теста. Использовалась движущаяся синтетическая сцена, а битрейты различались; это не сравнение равного визуального качества, не тест реального фильма и не замер интернета между друзьями. Эти числа не гарантируют результат релиза на другом ПК или через Radmin.

Нужны совместимая NVIDIA, актуальный драйвер и монитор, подключённый к NVIDIA. Зрителям NVIDIA не требуется. При уменьшении разрешения приложение просит Windows отключить рамку; если система отказывает, отсутствие индикатора не гарантируется. Автоматической подстройки GPU-битрейта под каждого зрителя пока нет. При проблемах уменьшите настройки либо выберите обычный захват.
