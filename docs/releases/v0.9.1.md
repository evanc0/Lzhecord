# Lzhecord 0.9.1 — приём GPU-видео и диагностика серого экрана
+
+Обновление для случая, когда ведущий видит локальный предпросмотр, а зритель остаётся с серым экраном. Работающий голосовой канал не гарантирует прохождение отдельного GPU-видеоканала.
+
+## Что изменилось
+
+- UDP-обмен GPU-видео перенесён в сетевой процесс **Lzhecord**. MediaMTX слушает только localhost. Это устраняет отдельную зависимость от сетевого доступа фонового MediaMTX.
+- Приложение выполняет встречный служебный UDP-обмен с адресами подключённого зрителя. Приём и маршрутизация выполняются отдельно для каждого зрителя; новый адрес принимается только после проверки ICE MESSAGE-INTEGRITY. Внешние STUN/TURN-серверы не добавлены.
+- Через локальный посредник проходят готовые зашифрованные WebRTC-пакеты. Повторного кодирования и передачи сырых кадров через Node нет; аппаратное сжатие остаётся прежним.
+- При блокировке автозапуска звука видео запускается без звука и показывает кнопку его включения. Убрана зависимость запуска изображения от разрешения на звук.
+- В диагностике появился отдельный блок приёма GPU-видео: ICE/соединение, наличие ответа ведущего, полученные байты/пакеты, декодированные кадры и состояние видеоплеера. Ошибки приёма сохраняются также в локальном журнале.
+- Если после подключения нет декодированных кадров, приложение сообщает об этом и ограниченно переподключается вместо бесконечного ожидания.
+
+## Проверено
+
+Целевые проверки: маршрутизация UDP, проверка ICE-пакетов, ограничения VPN/числа зрителей и поведение при запрете автозапуска. В собранном EXE реальный синтетический H.264-поток с аппаратным NVENC-кодированием и звук Opus прошли через новый канал к двум локальным зрителям. Проверены растущее число декодированных кадров, запуск видео без звука, включение звука по действию пользователя и продолжение просмотра вторым зрителем после отключения первого.
+
+Тест не захватывал рабочий стол пользователя. Полные проверки тем, профилей и остальных неизменённых функций не повторялись. Условия интернета/Radmin между разными ПК в этой локальной проверке не воспроизводились; проблемную пару компьютеров нужно проверить повторно.
+
+## Как проверить
+
+1. Закройте предыдущую версию и распакуйте **Lzhecord-Desktop-0.9.1-win-x64.zip** целиком. Рекомендуется обновиться **обоим участникам**. Протокол совместим с 0.8.x и 0.9.0.
+2. Можно перенести data/preferences.json и каталог data/media-tools при закрытых приложениях, чтобы сохранить настройки и уже скачанные кодеки. Сами пакеты кодировщиков в этом обновлении не менялись.
+3. Подключитесь к одной сети Radmin и выберите «Авто». Для GPU-видео используется **UDP 8790 приложения Lzhecord**. MediaMTX отдельного сетевого разрешения больше не требует.
+4. Если серый экран остаётся, сохраните диагностику **на обоих ПК**, пока комната открыта, и укажите, кто показывал экран. Теперь отчёт позволит отличить отсутствие сетевых пакетов от ошибки декодирования или воспроизведения.
